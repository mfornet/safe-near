\chapter{Introduction}

\section{The contract}

\texttt{wrap.near} is the wrapped NEAR fungible token (NEP-141), binary
\texttt{contracts/w-near/contract.wasm} with code hash
\texttt{DL2f5xmZ44cQRP6vBMt94rvseH5d5KKnAGis2WkTAsh1}, reproduced byte for
byte from \texttt{near/core-contracts} at commit \texttt{54f8267}, built with
Rust 1.51.0, near-sdk 3.1.0 and near-contract-standards 3.1.0. The contract
has fifteen exported methods: initialisation (\texttt{new}), wrapping
(\texttt{near\_deposit}, \texttt{near\_withdraw}), the NEP-141 core
(\texttt{ft\_transfer}, \texttt{ft\_transfer\_call},
\texttt{ft\_resolve\_transfer}, \texttt{ft\_total\_supply},
\texttt{ft\_balance\_of}, \texttt{ft\_metadata}) and NEP-145 storage
management (\texttt{storage\_deposit}, \texttt{storage\_withdraw},
\texttt{storage\_unregister}, \texttt{storage\_balance\_bounds},
\texttt{storage\_balance\_of}, plus the legacy
\texttt{storage\_minimum\_balance}).

\section{Structure of the verification}

The verification is organised in three layers.

\begin{enumerate}
\item \textbf{Model} (Chapter~\ref{ch:model}). A mathematical description of
  the contract state and of every method, written by hand from the Rust
  source. Each method is a function from a state and a host context to either
  a panic or an outcome (new state, promises, return value, logs). The
  mathematical model must be audited against the source; deployed conclusions
  also require audited runtime and adapter semantics and a refinement proof.
\item \textbf{Specifications} (Chapter~\ref{ch:spec}). Properties of the
  model stated as propositions, and their proofs (Chapter~\ref{ch:proofs}).
  They never mention WebAssembly.
\item \textbf{Refinement} (Chapter~\ref{ch:refinement}). The statement that
  the deployed binary, executed by the NEAR runtime in Lean, behaves exactly
  as the model, for every input, every amount of attached gas and every
  resource state. This is what transfers every proven property to the real
  contract. It is the generic \texttt{NearInterface.Refines}, instantiated
  with the near-lean runtime and the wNEAR contract model; its proof for
  \texttt{contract.wasm} remains open.
\end{enumerate}

A check mark on a definition records that its Lean statement exists; it does
not prove a proposition stated by that definition. Completed property proofs
appear as separate theorems in Chapter~\ref{ch:proofs}; deployed refinement
remains open.

\chapter{Refinement}
\label{ch:refinement}

The refinement statement is generic and lives in \texttt{near-lean/interface}
(\texttt{NearInterface.Refines}). Its only hypotheses are that the storage
represents a model state and that the context is one the runtime builds. It
says that the execution never reports an interpreter limitation; that with at
least the model's gas bound attached it agrees with the model exactly (return
value, storage, balance, storage usage, logs, receipts, failure) and uses at
most that much gas; that with less it agrees or fails for gas with no effects;
and that input that is no call fails with no effects.

\section{The contract model}

The model reads the context as near-sdk 3.1.0 does: account ids carry over
(nearcore's and the SDK's account-id rules are proved to agree), arguments
are decoded from JSON as serde\_json and the derived \texttt{Deserialize}
accept them, and the callback result is parsed as a JSON \texttt{U128}. A
successful \cref{def:step} is followed by the runtime's checks: promise
deposits against the liquid balance, and the storage stake of the new state.
Return values and receipts are compared as bytes, panics by their exact
messages. The gas bound pays the longest possible trie path for every storage
key a call touches; that it holds is part of the obligation, and the adapter
tests check it on adversarial tries.

\section{The obligation}

\texttt{NearRuntime.Boundary} instantiates the runtime: one function-call
action of near-lean's VM followed by the receipt's storage-stake check, with
every failure rolling back storage, balance, usage and receipts. The theorem
below, with the binary embedded, is the formal deployed refinement
obligation. It is not proved.

\section{Walking skeleton: M2 in progress}

The next milestone exercises the metered proof infrastructure on a small
independent module before applying it to the deployed Rust binary. Its
\texttt{save} method reads input, writes storage, logs a message and returns
the input. The independent model includes resource-limit and storage-stake
failures. Executable scenarios compare it with the actual receipt boundary
at exact and smaller burn and prepaid budgets; these are validation, not
universal proofs.

The kernel has checked gas-credit spending and composition, rules for
constants and locals, an exact symbolic constant-return execution, host
billing lists, and contracts for input and output hosts. The storage-write
functional core and storage-usage arithmetic are checked separately from
local trie lookup, dereference and accounting obligations. Boundary adequacy
covers success, VM abort, receipt validation and storage-stake failure.
Prepared-memory validation, exact key/log reads, actual startup and entry
activation are checked. The fifteen-opcode success body composes input, log
and return contracts with one explicit local storage frontier.

The original context premise admitted duplicate overlay keys whose view and
lookup disagree. Kernel-backed counterexamples reach an execution issue in
both the skeleton and deployed wNEAR. The corrected premise adds uniqueness
within each overlay, with preservation proofs for actual runtime operations;
prospective writes may still override committed writes. This substantive
premise correction is recorded in the misstatement log.

The actual input-size, key-length and value-length failures now match the
independent model through public receipt execution with exact billing and
residual credits. The key/value branches use no trie or proof-size premise.
The log-count rejection after a completed storage write is checked through
actual execution using the existing local storage frontier and resource frame.

Trie compact paths, leaf/extension/branch decoding, generated bitmaps, actual
branch construction from child equations and branch lookup composition are
kernel checked. Successful lookup access counts are bounded by twice the byte
key length plus one terminal node and an optional value dereference. The
actual decoder rejects empty extension paths, so this bound needs no extra
witness-shape premise. General canonical lookup correctness remains open;
singleton lookup retains its explicit nonzero-root obligation.

Actual machine budget compatibility now includes the direct storage call and
metered advance alongside input/log/return and pure instructions. Storage
readiness is supplied only at the actual low paid state, while continuing
outcomes preserve issue freshness and every outcome preserves logs. Whole-run
phase invariants and derivation of readiness from canonical storage remain open.

The empty-base specialization derives storage postconditions from original
context data and matches the model for both storage-stake acceptance and
rejection. Its context-only cost includes loading, 23 regular operations,
ordered storage/input/log charges and per-receiver return-data byte fees.
Original gas-limit coverage supplies credits, model matching and a used-gas
bound; the log decoder's width check follows from WF and this coverage. The
proof-size check and usage room remain explicit, and the universal model gas
function and low-gas refinement clause remain open.

The current statement also has the separately documented SAF-67 gap: an
arbitrary recorded-proof-size input is accepted by context WF. A canonical
empty-context probe makes deployed wNEAR new fail for the proof limit while
the model succeeds with ample gas. WF and conditional non-refinement are
kernel proved; the deployed outcome is executable-checked. A faithful recorder
requires explicit object/removal/code history and a receipt baseline; no
unproved universal size bound has been added to WF.

The pinned protocol also needs a kernel certificate interface: the JSON parser
used by the configuration loader contains opaque partial definitions, so even
an empty-object parse cannot be certified by kernel reduction. Numeric facts
about the pinned JSON were not replaced by unchecked computation or new axioms.

M2 remains open: faithful recorder input, nonempty canonical-trie correctness,
the full storage contract and gas bound, other deterministic failures and
whole-run simulation must be closed before assembly of \texttt{Refines}.
The deployed \texttt{refines\_wnear\_exported} proof remains open. The
detailed frontier is recorded in \texttt{notes/todo/wnear\_refinement\_proof.md}.
Run \texttt{just wnear-skeleton} for the executable checks and
\texttt{just wnear-proofsize-probe} for the open SAF-67 counterexample.
