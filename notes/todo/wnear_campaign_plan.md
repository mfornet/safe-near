# wNEAR refinement: campaign plan

How to take [PR #40](https://github.com/mfornet/safe-near/pull/40) to a
finished `refines_wnear` without wasted work. It extends
[`wnear_refinement_proof.md`](wnear_refinement_proof.md) (the milestones,
principles and agent policy, which stand) with what the state of the PR on
2026-10-31 showed was missing: statement hardening at the top, a progress
metric that cannot be gamed, independent audit, and timeboxes with fallbacks
decided in advance.

No plan guarantees a proof. This one guarantees that a false or unprovable
piece is found early, that nothing vacuous is marked proved, and that no week
is spent on work that is later discarded.

## State on 2026-10-31

- Proved, standard axioms only, under five pinned-protocol premises:
  `ft_total_supply`, `storage_minimum_balance`, `storage_balance_bounds`,
  `ft_metadata`, `new`, `near_deposit` (6 of 15).
- Critical path: the gas bound of serde_json's parser. `ft_balance_of` is
  Conditional on `SelectedParserLinearBudget`; the eight open methods all
  need the same parser. Every commit of 2026-10-31 (25 commits, +54k lines)
  is on this leaf, still open.
- Statement risks on record (the feasibility register on the branch,
  `notes/todo/wnear_feasibility_risks.md`): `hprotocol` may be vacuous
  (`Lean.Json.Parser.anyCore` is opaque, the kernel cannot evaluate it); the
  five protocol facts are sorried; incoming-receipt validation is unmodeled
  in `applyAttempt`; `Context.WF` has no promise-result byte bound, which
  `ft_resolve_transfer` needs; the parser's all-outcome cost bound is
  quadratic while the model allowance is linear.
- Process: 519 commits ahead of `main`, five merge conflicts, no CI run
  since 2026-10-30 (the fv01 runners offline), `STATEMENTS.md` (1.76 MB)
  regenerated by every commit, a 3,000-line status note. None of it has been
  audited by anyone but its author.

## Principles added

1. **Witnesses before statements, statements before proofs.** Every
   hypothesis of a top-level theorem gets an executable witness, a concrete
   value satisfying it, checked in CI. A theorem whose hypotheses have no
   witness is vacuous and counts as no progress. Today this check is missing
   for `hprotocol`.
2. **The frontier delta is the only progress metric.** Progress is the
   number of named open obligations closed (from `blueprint/frontier.json`)
   and the `sorry` count, per merge. Lines of Lean added are a cost. An
   agent that merges commits with a frontier delta of zero is stopped and
   re-planned.
3. **Author and auditor are different model families.** Every statement
   change is reviewed, against the checklist below, by an agent that did not
   write it. Shared blind spots are the main way a wrong statement survives.
4. **Timeboxes with pre-approved fallbacks.** Every leaf on the critical
   path has a timebox and a fallback written down now, so a stall becomes a
   decision instead of a sunk cost.
5. **Small merges, green CI, always.** The campaign branch merges to `main`
   at least weekly. No more 500-commit branches.

- Record the baselines the budgets below are set against: clean build time
  of `Proofs` on both machines, incremental build time for a leaf-file
  change, the `sorry` count (19 on 2026-10-31: 18 in `Proofs/Refinement.lean`,

  status.
- Infrastructure, half a day each: split `STATEMENTS.md` into one file per
  module so diffs are reviewable; a `frontier-delta` script printing the
  obligations closed and opened between two revisions; the status note gets
  a generated frontier table instead of prose "Continuation" sections.

## Phase 2: close the parser (timebox: 3 weeks)

One Opus architect owns the decomposition: the remaining inequality is split
into independent, validated leaf lemmas with fixed statements, one file each,
every one with a harness test that would catch a false statement. Then:

- Sonnet and Codex provers take leaves with known patterns, in parallel
  worktrees. Four to six concurrent builds are comfortable on 32 cores.
- DeepSeek takes leaves that are fully specified: a fixed statement, the
  allowed imports listed, a checker (`lake build` of that file and the axiom
  audit, with a timeout). Many candidates run in parallel; only what the
  checker passes is accepted. This is the cheap, embarrassingly parallel part.
- Kill criterion: a frontier delta of zero for three consecutive days on the
  parser stops the work and applies §10.3 of the proof plan: restate, split,
  or trigger S6.

## Phase 3: the methods (2–4 weeks)

With the parser contract closed, the seven non-promise methods are mostly
composition of existing pieces (storage writes from `near_deposit`,
formatting and panics done). One prover per method, independent files, a
`refinement-stress` round before each as M8 prescribes. `ft_transfer_call`
and `ft_resolve_transfer` last, gated on S3 and S4.

## Phase 4: M9 (1 week)

Discharge the S1 and S2 leaves; `just wnear-audit` with no `sorry`
allowance; the blueprint shows nothing proved that is not.

## Agents

| Role | Model | Why |
|---|---|---|
| Architect (1) | Opus | Owns statements, decomposition and fallback decisions. The only agent that changes a contract. |
| Auditor (1–2) | Opus, or Codex when the author was Claude | Reviews every statement change with the checklist. Never the author. |
| Provers (4–6) | Sonnet, Codex | A validated leaf with a known pattern; one file, one worktree each. |
| Grinders (many) | DeepSeek | A fully specified leaf with a checker; fuzzing; counterexample search; transcription. Cheap and parallel; accepted by the checker only. |
| Runner (1) | Haiku | Harness, scenarios, audit, frontier delta and build-time report after every merge. |
| Integrator (1) | Sonnet | A serial merge queue: runs the strict checkpoint, enforces the gates, merges or bounces. |

Escalation as in §11.2 of the proof plan: two failures move a task one tier
up, and the task type is logged.

**Auditor checklist.** Every hypothesis has a witness; no sorried lemma is
cited as proved; cost bounds match harness measurements; pinned statements
are byte-identical or the diff is explained; no new axioms; every domain
premise cites a nearcore line at the pinned revision; the build-time budget
holds.

## Merge gates

The Integrator enforces them; CI backs them. Build green on both runners;
the axiom audit; statement pins unchanged or reviewed; frontier delta at
least zero; harness and scenarios pass; clean-build time within 10% of the
baseline; the status note changed by the generated table only.
