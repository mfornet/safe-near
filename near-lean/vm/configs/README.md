# NEAR runtime configs

JSON dumps of nearcore's `RuntimeConfig` (gas costs, fees and limits), one
file per protocol version at which the config changed. Generated by
`tools/dump-runtime-config` from `near-parameters 0.37.4`
(`PROTOCOL_VERSION = 86`); do not edit by hand. The `runtime_finance` object adds
source-derived refund penalties and the `AccountCostIncrease` feature flag
which the RPC view does not expose; `runtime_admission` carries the transaction admission
flags (strict nonces, V1 transactions, signature size); `runtime_extra` carries what the M3b
runtime needs and the RPC view omits (listed below); `compute_costs` lists the ExtCosts and
action fees whose compute cost differs from their gas cost (absent means equal). Regenerate with:

```sh
cd tools/dump-runtime-config && cargo run --release -- ../../near-lean/vm/configs
```

## Files

`runtime_config_v<version>.json` holds the config in force from protocol
version `<version>` up to (but excluding) the next listed version. The
config for an arbitrary version `p` is the file with the largest `<version>`
such that `<version> <= p`. Versions below 29 (mainnet genesis) are not
covered.

| file | notable changes vs previous file |
|------|----------------------------------|

## `runtime_extra`

Source-derived parameters of global contracts, gas keys, delegation and promise yields.
Fees are `{ send_sir, send_not_sir, execution }` objects; the flags are `ProtocolFeature::*.enabled(version)`.

| key | meaning |
|-----|---------|
| `action_fees.deploy_global_contract_base` / `_byte` | `DeployGlobalContract` send and execution fees |
| `action_fees.use_global_contract_base` / `_byte` | `UseGlobalContract` fees |
| `action_fees.gas_key_transfer_base`, `gas_key_byte`, `gas_key_nonce_write_base` | `TransferToGasKey`/`WithdrawFromGasKey` and gas-key creation fees |
| `global_contract_storage_amount_per_byte` | yoctoNEAR per byte of global contract code, the deployer's burnt storage cost (decimal string) |
| `deploy_global_contract_execution_base` / `_per_byte` | gas of the distribution receipt (`fees.deploy_global_contract_execution_*`) |
| `include_deploy_global_contract_outcome_burnt_storage` | the deploy outcome includes the burnt storage in `tokens_burnt` |
| `global_contract_distribution_nonce` | distribution receipts carry a per-identifier nonce |
| `fix_delete_account_global_contract_storage_usage` | `DeleteAccount` counts global contract identity bytes towards the remaining storage |
| `fix_delegate_action_deposit_with_function_call_error` | delegate actions reject deposits with function calls |
| `delegate_v2` | `DelegateAction` V2 (monotonic nonce lanes) is accepted |
| `yield_with_id` | `promise_yield_create_with_id` host function |
| `eth_implicit_global_contract` | ETH-implicit accounts use the wallet global contract (before it, local legacy code, reported unsupported) |

## JSON shape

Top level (all files):

```
storage_amount_per_byte      string  (u128 yoctoNEAR as decimal string)
transaction_costs            object
wasm_config                  object
account_creation_config      object
congestion_control_config    object
witness_config               object
min_gas_purchase_price       string  (u128 decimal string)
account_creation_charge      string  (u128 decimal string)
```

Representation rules:

* `Gas` / `u64` / `u32` / `u8` values are JSON integers (up to `2^63-1`
  appears, e.g. `congestion_control_config.min_tx_gas` in v67).
* `Balance` (u128) values are JSON strings of decimal digits.
* `Rational32` values are 2-element arrays `[numerator, denominator]`.
* Fees are objects `{ "send_sir": int, "send_not_sir": int, "execution": int }`.
* `reject_tx_congestion_threshold` is a JSON float.
* `vm_kind` and `storage_get_mode` are enum names as strings.
* `account_id_validity_rules_version` is an integer (0, 1 or 2).

`transaction_costs`:

```
action_receipt_creation_config         Fee
data_receipt_creation_config           { base_cost: Fee, cost_per_byte: Fee }
action_creation_config
  create_account_cost                  Fee
  deploy_contract_cost                 Fee
  deploy_contract_cost_per_byte        Fee
  function_call_cost                   Fee
  function_call_cost_per_byte          Fee
  transfer_cost                        Fee
  stake_cost                           Fee
  add_key_cost
    full_access_cost                   Fee
    function_call_cost                 Fee
    function_call_cost_per_byte        Fee
  delete_key_cost                      Fee
  delete_account_cost                  Fee
  delegate_cost                        Fee
storage_usage_config                   { num_bytes_account: int, num_extra_bytes_record: int }
burnt_gas_reward                       [int, int]
pessimistic_gas_price_inflation_ratio  [int, int]
ml_dsa_65_verification_cost            int
```

`wasm_config`:

```
ext_costs             object: host-function cost name -> int gas (same key set in all files)
grow_mem_cost         int
regular_op_cost       int
linear_op_base_cost   int
linear_op_unit_cost   int
vm_kind               string ("Wasmtime" in all files)
discard_custom_sections, global_contract_host_fns, reftypes_bulk_memory,
gas_key_host_fns, one_yocto_on_promise, p256_verify_host_fn,
yield_with_id_host_fns, chain_id_host_fn, bls12381_not_in_group_fix,
fix_contract_loading_cost, implicit_account_creation, eth_implicit_accounts,
eth_implicit_global_contract              bool
storage_get_mode      string ("Trie" or "FlatStorage")
limit_config          object: limit name -> int (key set grows over versions)
```

`limit_config` keys that are not present in every file:
`max_functions_number_per_contract` (from v49), `max_locals_per_contract`
(from v53), `max_tables_per_contract` and `max_elements_per_contract_table`
(from v82), `max_params_per_contract`, `max_params_per_function`,
`max_operand_stack_bytes_per_function`, `max_function_body_size`,
`max_instrumented_code_size`, `max_blocks_per_function`,
`max_blocks_per_contract`, `max_types_per_contract` (from v84). A parser
should treat these as optional.

`account_creation_config`:

```
min_allowed_top_level_account_length   int
registrar_account_id                   string
```

## Not covered

The JSON is nearcore's `RuntimeConfigView`, which omits: action fees for
global contracts, deterministic state init and gas keys
(`ActionCosts` 16..=25), `gas_refund_penalty` / `min_gas_refund_penalty`,
global-contract compute costs, `global_contract_storage_amount_per_byte`,
`bandwidth_scheduler_config`, `use_state_stored_receipt`, and the per
host-function compute costs (only gas is emitted). See
`tools/dump-runtime-config/README.md`.

The native `wasm_config.vm_kind` selector depends on the generator's host
architecture (these committed tables were generated on ARM with Wasmtime).
The Lean configuration loader does not consume this field. CI runs
`tools/check_runtime_configs.py` against regenerated tables: it validates the
backend enum and reports selector differences, then requires exact structural
equality for every other field and the complete file set. nearcore's own
configuration snapshots similarly redact this selector. The original generated
JSON remains intact; no fees, feature flags or limits are normalized.

The generated `runtime_finance` supplement contains `account_cost_increase`,
`gas_refund_penalty` and `min_gas_refund_penalty`. The RPC view omits these refund
fields; the dumper reads them from the internal pinned configuration. Receipt
purchase pricing also loads `min_gas_purchase_price` and `account_creation_charge`.
These financial comparisons do not establish historical execution conformance.

`runtime_admission.strict_nonce` is generated from the pinned feature table and
controls strict sequential transaction nonces (enabled from v85).

`runtime_admission.v1_transactions` is generated from the pinned
`ProtocolFeature::GasKeys` gate for the V1 transaction envelope. This is
independent of `runtime_admission.strict_nonce` (`StrictNonce`), even though
both become enabled at protocol 85 in this source revision. Ordinary-key V1
transactions are supported; this flag does not assert modeled gas-key lanes.
