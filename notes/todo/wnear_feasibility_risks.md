# wNEAR refinement feasibility risks

This register tracks end-to-end uncertainties, not a completion percentage.
The target statements and environmental assumptions must not be weakened to
turn an unresolved risk into a proof.

| Gate and risk | Evidence and status | Next discriminating check | Consequence if it fails |
| --- | --- | --- | --- |
| Foundation: pinned protocol availability and environment | `PinnedProtocolAvailable` is an existential proposition with no proof. Five protocol facts in `Proofs.Refinement` are admitted. A timeboxed kernel probe gets stuck even on `(Lean.Json.parse "{}").isOk = true`: `Lean.Json.Parser.anyCore` is an opaque partial definition. The runtime adapter loads version 86 with the same parser and the feasibility test checks all numeric fields in `CostsV86`, `LimitsV86`, `CostsNewV86`, and `CostsDepositV86`, memory-page values, and module preparation. These executable observations are not kernel proofs of parse existence or the universal implications. | Investigate a kernel-checkable parsing interface and an explicit equivalence to the current opaque parser; without such a bridge, a total replacement changes the stated protocol interface and needs review. Prove the exact parse result exists and each original implication; do not use `native_decide` or insert a new axiom. | If the parser cannot produce a value, the universal `hprotocol` theorem is vacuous; if a bound fails, completed method proofs cannot be instantiated as claimed. |
| Foundation: external assumptions and ownership | `MethodClause` quantifies over all represented states and `Context.WF` contexts before invoking `At`; the decoded body lemma assumes specific heap, frame, trie, parser room and gas resources. The path is not yet derived from that quantifier context. | Instantiate these premises at the actual method entry, checking nonempty witnesses, quantifier order, separation ownership and storage accounting, without adding context assumptions. | An unreachable resource precondition or incompatible ownership would invalidate the claimed route to the unchanged top-level theorem. |
| General argument: successful JSON parser and gas | `roomRun`, changing scratch allocations, deep ignored values, and the parser's interface remain open. A conservative all-outcome `costRun` has a proved quadratic lower bound, whereas the model allowance is linear in argument length. Successful escape decoding already gives `escK = out.length`; this supports, but does not prove, a `roomRun` induction aligned with `appendChunks`. Adversarial runs at nesting depths through 4096 and repeated escapes through 16384 matched the model and its unchanged gas allowance. | Derive `roomRun` from caller resources along successful parse traces and prove a bound using the actual trace rather than the quadratic all-outcome bound. Increase and diversify adversarial inputs, including escaped account IDs and object keys. | An execution exceeding the model allowance would be a counterexample requiring an explicit model/specification decision; otherwise an oversized proof bound may require a different analysis rather than a specification change. |
| General argument: rejection and arbitrary resources | `ftBalanceOf_no_issue_obligation`, accepted, and rejected branches are admitted. Adapter probes near observed and model gas thresholds and three malformed ignored values passed; these sample one represented context and cannot establish the universally quantified rollback and no-execution-issue clauses. | Exercise gas around actual cutoffs, memory and proof limits, malformed UTF-8, nesting and parser errors; prove rollback and permitted failure classification at the actual boundary, including quantifier and framing obligations. | A trap, interpreter limitation, non-rollback or disallowed resource failure contradicts the target, while proof-only cost overestimation indicates an analytical problem. |
| Asynchronous boundary | Adapter tests compare `ft_transfer_call` receipt observations and several `ft_resolve_transfer` promise-result cases; both full method clauses remain admitted and there is no checked end-to-end receipt/callback composition. | Identify one represented transfer-call, inspect receipt construction and attached gas, execute the callback with partial/failed results, and connect concrete observations, rollback and gas to the model in a checked composition. | Receipt, callback or resource behavior that differs from the model could require a specification correction; otherwise missing host contracts and frame proofs are proof gaps. |

At each checkpoint record the exact failing input, result and source digest for a
counterexample; distinguish interpreter/model mismatch from a failed proof or an
unnecessarily weak bound. Tests are evidence, not replacements for the universal
kernel-checked obligations.
